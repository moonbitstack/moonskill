Agent Skills · the document, read and judged

Every skill is a résumé.The agent that reads it is the one hiring.

A skill is a directory with a SKILL.md. The header names it and says what it is for; the body is what a model reads once it has picked this one. moonskill reads that document in MoonBit, judges it against the specification, and writes the one-line entries a model chooses from.

01Summary

A short document, read at three depths

Skills are cheap because nobody reads all of them. A client puts the name and description of every skill it has in front of a model, opens the body of the one the model picked, and reads the files that body points at only when the work reaches them. The specification calls that progressive disclosure; the effect is a shortlist that costs a line until something is needed.

This library is the reading side of that arrangement. It parses the header strictly, reports every rule a document breaks in one pass, walks a tree of skills through a source you implement, and produces the block a model chooses from. It has no opinion about which agent is reading, and it opens no file by itself.

02What it does

Five things, one document format

  • parse Reads the fence and the frontmatter with a strict YAML reader, so name: 42 is the name forty-two. A document that is not a skill document at all is refused; a field that is merely wrong is left for validate to report.
  • validate Holds the document to every rule the specification states — the three length limits, the character rules, the directory name, the fields that may appear — and returns the whole list at once. A person fixing a document wants the list, not the first line.
  • discover Walks a tree of skills through Source, a two-method trait. A directory reader is included; a tarball, a database or an HTTP cache is a source you write, and everything above it stays as it is.
  • prompt Writes the first tier as an <available_skills> block: name, description and location per skill, escaped so a description that quotes markup stays text.
  • skillcheck The same judgement from a shell. --json for a program to read, a non-zero exit for a script to stop on.
03The three tiers

What a model sees, and when

The specification loads a skill in three steps. Each one has a shape in this library, and nothing is read twice or read early.

The three tiers of a skill and the API that reads each
TierWhat is readHow
1Name and description of every skill on offerSkill::summary, prompt
2The body of the one skill that was chosenSkill::body
3One file that body points at, when the work reaches itSkill::resolve then Source::read

Skill::resolve joins the skill root and refuses a path that climbs out of it, so a document can point at its own files and nowhere else. The document itself is read the same way as any other file.
